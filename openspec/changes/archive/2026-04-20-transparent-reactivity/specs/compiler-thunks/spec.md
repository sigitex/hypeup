## ADDED Requirements

### Requirement: Element arguments wrapped in thunks
The babel plugin SHALL wrap each argument in `elem()` and `elemVoid()` calls in an arrow function thunk `() => expr`. This defers evaluation so that reactive property reads happen inside mount-time effects, not eagerly in the component body.

#### Scenario: Simple element arguments become thunks
- **WHEN** source contains `div("hello", myVar)`
- **THEN** output SHALL be `elem("div", [() => "hello", () => myVar])`

#### Scenario: Element with class chain and arguments
- **WHEN** source contains `div.active(myExpr, "text")`
- **THEN** output SHALL be `elem("div", [className("active"), () => myExpr, () => "text"])`

#### Scenario: Void element arguments become thunks
- **WHEN** source contains `input({ type: "checkbox" }, myBinding)`
- **THEN** output SHALL be `elemVoid("input", [() => ({ type: "checkbox" }), () => myBinding])`

### Requirement: className calls are not wrapped in thunks
`className()` calls generated by class chain lowering SHALL NOT be wrapped in thunks. They are always static string arguments.

#### Scenario: className not double-wrapped
- **WHEN** source contains `div.active("hello")`
- **THEN** output SHALL be `elem("div", [className("active"), () => "hello"])` — the `className("active")` SHALL NOT be wrapped in a thunk

### Requirement: Nested element calls produce thunks at each level
When element calls are nested, each level SHALL independently wrap its own arguments in thunks.

#### Scenario: Nested elements
- **WHEN** source contains `div(span("inner"))`
- **THEN** output SHALL be `elem("div", [() => elem("span", [() => "inner"])])`

### Requirement: Non-element transforms are not affected
CSS property, at-rule, rule, and escape-hatch transforms SHALL NOT be modified. Only `elem()` and `elemVoid()` argument arrays SHALL have thunk wrapping.

#### Scenario: CSS property unchanged
- **WHEN** source contains `color("red")`
- **THEN** output SHALL be `prop("color", "red")` — no thunk wrapping

#### Scenario: Rule unchanged
- **WHEN** source contains `rule(".foo", color("red"))`
- **THEN** output SHALL be `rule(".foo", [prop("color", "red")])` — no thunk wrapping on rule args
